# 請求・入金管理レポート

中小企業の経理向けに、**請求書のCSVを取り込むだけで、入金状況の判定・売掛金の見える化・月次レポート・請求書PDFの発行**までを行うWebアプリです。
ログインやデータベースは不要で、ブラウザだけで動きます。

- 公開URL：（公開後に記載）
- ソースコード：https://github.com/mianzelizi-maker/invoice-report
- サンプルデータ入り：画面の「サンプルデータで試す」ボタンですぐに動作を確認できます

## 背景・目的

中小企業の経理では、請求書と入金の突き合わせを Excel やスプレッドシートで手作業していることが多く、次のような悩みが起きがちです。

- 「入金済み／一部入金／未入金／支払遅延」の判定と、遅延日数の数え上げに手間がかかる
- どの取引先にいくら売掛金が残っているか、どこから先に回収すべきかが、一目で分からない
- 月次の売掛金報告を毎月、文章にまとめ直している
- 請求書の作成（採番・明細・消費税の計算）が手作業で、計算ミスや番号の重複が起きる
- CSVを取り込むときの入力ミス（数値でない値・日付の誤りなど）が、どこにあるのか分かりにくい

これらを、**CSVを取り込めば自動で判定・集計・文章化・請求書発行までできる**形にまとめ、経理担当者の月次作業の手間とミスを減らすことを目的に、企画・設計・実装・テスト・公開までを一人で行いました。

## 主な機能

| 機能 | 内容 |
|---|---|
| **CSV取り込みと検証** | 請求書CSV（取引先・請求番号・請求日・請求額・支払期日・入金日・入金額）を取り込む。誤りは「何行目・どの列・どんな誤りか」で表示し、誤り行を除いて取り込むこともできる。Excelの Shift_JIS にも対応 |
| **入金状況の自動判定** | 入金済み／一部入金／未入金／支払遅延を自動判定し、遅延日数を計算。一部入金のうえ遅延している請求書は「一部入金・遅延」と表示 |
| **ダッシュボード** | 売掛金残高・今月の回収予定・遅延額・回収率、年齢別残高、月別の請求・入金・売掛金の推移。「回収を急ぐべき取引先」と「支払いが遅れがちな取引先」を分けて表示 |
| **請求書一覧・取引先別** | 状態や取引先で絞り込み・並び替え。遅延を色で強調。PCは表、スマホはカード表示 |
| **月次レポート** | 集計結果を文章にする。**APIキーがなくても動く「自動集計」**と、Claude API による「AI生成」を選べ、どちらの文章かを画面に表示。AIは1日の利用回数に上限あり |
| **請求書PDFの発行** | 宛先・明細・税率（10%／軽減8%／非課税）を入力して、日本語のPDFを出力。請求番号の自動採番、小計・消費税・合計の計算、発行日・支払期日の記載。宛先はフリガナ・かな・全半角の違いを区別せず検索できる |

スマートフォンでも見やすいよう、PCは左サイドバー、スマホは下部タブバーで操作します。

## 工夫した点

1. **判定ルールを言葉で定義し、テストで固定した**
   「期日当日は遅延ではない」「残高があり期日を過ぎていれば、一部入金でも遅延を優先する」「遅延日数は『いま遅れている日数』と『過去に遅れて入金された日数』を分けて数える」など、経理の現場で解釈が割れやすい点を先に決め、境界値（期日の前日・当日・翌日など）をテストにしました。
2. **APIキーの漏えいと、料金の膨張を仕組みで防いだ**
   キーはサーバー側の環境変数だけに置き、ブラウザにもGitHubにも出しません。公開版では「キーと利用回数のカウンタの両方がそろったときだけAIを有効」とし、訪問者ごと・サービス全体の1日の上限、入力の厳格な検証、出力長の固定、リトライなしなどで、最悪でも1日約50円に収まる設計にしました。上限の動作はテストで確認しています。
3. **AIが使えなくても、常に使える**
   キー未設定・上限到達・API障害のときは、集計結果からルールで作る文章に自動で切り替わります。どちらの文章かは「AI生成」「自動集計」のバッジで常に分かります。
4. **CSVの誤りを、原因の行と列まで示す**
   「12行目の請求額『abc』が数値ではありません」のように表示し、その誤りから派生する指摘（例：入金額が数値でないために「入金額が空」と重ねて出す）は抑えて、直すべき箇所だけを見せます。
5. **請求書の計算を、実務の考え方に合わせた**
   消費税は、税率ごとの合計に対して1回だけ円未満を切り捨てます（明細ごとに丸めると1円ずれる例をテストにしました）。請求番号は同じ年月の最大連番の続きから自動採番します。
6. **重い部分は、必要なときだけ読み込む**
   PDFのライブラリと日本語フォントは、「請求書PDFを作成」を押したときにだけ読み込むので、通常の画面は軽いままです。
7. **数字が合わないという違和感を、原因まで切り分けた**
   サンプルの2社で遅延の数字が同じに見えた際、計算ではなくサンプルデータの設定（基準日とのずれ）が原因だと突き止めて修正し、意図した傾向をテストに固定しました。

## 現状の制約と今後の展望

**現状の制約**

- データはブラウザの中だけで扱い、ページを再読み込みすると消えます（ログイン・データベースなし）。発行元の情報と発行履歴だけ、このブラウザに保存します
- 1つの請求書につき入金は1回分（入金日1つ）で、分割入金の履歴は持てません
- 請求書は適格請求書の主な記載事項（登録番号・税率ごとの対象額と消費税額など）を備えますが、あらゆる書式の要件を網羅したものではありません
- AI生成の文章は、集計値をもとにしていても誤りを含む可能性があるため、数値は画面の集計と照合する前提です
- 数万件を超える大量データでの動作は検証していません

**今後の展望**

- ログインとデータベースを導入し、複数人・複数端末で使えるようにする
- 分割入金の履歴、入金の消込、督促メールの文面の下書き
- 会計ソフトや銀行の入出金データとの連携
- 請求書の履歴管理と再発行、書式の切り替え

## 起動方法（初心者向け）

自分のパソコンで動かす手順です。

1. **Node.js をインストールする**：[Node.js の公式サイト](https://nodejs.org/) から「LTS」版をダウンロードしてインストールします。終わったら、ターミナルで `node -v` と入力して、バージョン番号が表示されればOKです
2. **このフォルダでターミナルを開く**：エクスプローラーで `⑤portfolio` フォルダを開き、アドレスバーに `powershell` と入力して Enter を押します
3. **部品をインストールする（最初の1回だけ）**

```
npm install
```

4. **アプリを起動する**

```
npm run dev
```

5. ターミナルに表示された `http://localhost:5173/`（番号は変わることがあります）をブラウザで開き、「サンプルデータで試す」を押します
6. 終了するときは、ターミナルで `Ctrl + C` を押します

| コマンド | 内容 |
|---|---|
| `npm test` | 自動テストを実行する（129件） |
| `npm run build` | 公開用のファイルを作る（`dist` フォルダ） |
| `npm run sample` | サンプルCSV（`public/sample.csv`）を作り直す |

> パソコン上（`npm run dev`）では、月次レポートは「自動集計」の文章だけが表示されます。AI生成は、公開後に、Vercel で設定したときだけ使えます。

## 公開手順（初心者向け）

作業の流れは「① GitHubにアップロード → ② Vercelで公開 → ③（任意）AIレポートを有効にする」です。
**③をしなくても、②までで公開できます**（その場合、月次レポートは「自動集計」の文章だけが表示されます）。
画面の名前や場所は、各サービスの更新で少し変わることがあります。

### ① GitHub にアップロードする

1. [GitHub](https://github.com/) のアカウントを作り、右上の「＋」→「New repository」を選ぶ
2. Repository name に `invoice-report` などと入力する。**「Add a README file」などのチェックは入れない**（空のまま）。「Create repository」を押す
3. 作成後に表示される URL（`https://github.com/あなたのユーザー名/invoice-report.git`）をコピーする
4. このフォルダでターミナルを開き、次を1行ずつ実行する（1回目のコミットはすでにできています）

```
git remote add origin https://github.com/あなたのユーザー名/invoice-report.git
git branch -M main
git push -u origin main
```

5. **APIキーが含まれていないか確認する**。次を実行して、表示が `.env.example` だけ（または何も出ない）であればOK

```
git ls-files | findstr env
```

### ② Vercel で公開する

1. [Vercel](https://vercel.com/) を開き、「Continue with GitHub」でログインする
2. 「Add New… → Project」を選び、`invoice-report` の右の「Import」を押す
3. 「Framework Preset」が **Vite** になっていることを確認し、そのまま「Deploy」を押す（1〜2分）
4. 完了すると `https://invoice-report-xxxx.vercel.app` のような URL が発行される。これが公開URL

以降は、`git push` するたびに自動で公開内容が更新されます。

### ③（任意）AIレポートを有効にする

AI生成には、**Claude API のキー**と、**利用回数を数えるデータベース（Upstash）**の両方が必要です。
どちらかが欠けていると、安全のためAI生成は使えません（自動集計は使えます）。

#### A. Claude Console で APIキーを作る

Claude API は、Claude.ai の有料プランとは**別の課金**です。使った分だけの従量課金（前払い）です。

1. [Claude Console](https://console.anthropic.com/) を開く（`platform.claude.com` に移る場合があります）。メールアドレスなどでアカウントを作り、ログインする
2. 左のメニューの「Billing（請求）」を開き、クレジットを購入する。**最初は5ドルで十分**です。自動でチャージする設定（Auto reload）は、**オフのまま**にしておく
3. 「Limits（制限）」の項目で、**月の利用上限額**を設定する（例：5ドル）。これがいちばん確実な安全装置になります
4. 「API keys」を開き、「Create Key」を押す。名前は `invoice-report` などにして作成する
5. **表示された `sk-ant-` で始まるキーをコピーして、すぐに安全な場所（パスワード管理アプリなど）に保存する**。この画面を閉じると、二度と全体を見ることはできません

> **キーの扱い（重要）**：キーはパスワードと同じです。README・ソースコード・GitHub・チャット・スクリーンショットに**絶対に貼らないでください**。
> 万一、公開してしまったら、Console の API keys で**すぐにそのキーを削除（Delete）**し、新しく作り直してください。

#### B. Upstash で「1日の利用回数」を数えるデータベースを作る

これは、AIの使いすぎを防ぐために、利用回数を記録する小さなデータベースです（無料枠で足ります）。

1. [Upstash](https://upstash.com/) を開き、GitHub や Google でサインアップ／ログインする
2. 「Redis」→「Create Database」を押す
3. 次のように入力して「Create」を押す
   - Name：`invoice-report-limit`（好きな名前でOK）
   - Type：Regional
   - Region：日本に近い `ap-northeast-1`（Tokyo）
   - Plan：**Free**
4. 作成された画面の「**REST API**」の欄に、次の2つが表示されている。どちらも後で使うのでコピーしておく
   - `UPSTASH_REDIS_REST_URL`（`https://` で始まる）
   - `UPSTASH_REDIS_REST_TOKEN`（長い文字列。キーと同じく**他人に見せない**）

#### C. Vercel に設定を登録する

1. Vercel でこのプロジェクトを開き、上のメニューの「Settings」→「Environment Variables」を開く
2. 次の3つを1つずつ追加する（Name と Value を入力して「Save」）

| Name | Value |
|---|---|
| `ANTHROPIC_API_KEY` | A でコピーした `sk-ant-…` |
| `UPSTASH_REDIS_REST_URL` | B でコピーした URL |
| `UPSTASH_REDIS_REST_TOKEN` | B でコピーしたトークン |

   （必要なら `AI_DAILY_LIMIT_PER_IP`（1人1日あたりの回数、既定3）、`AI_DAILY_LIMIT_TOTAL`（全体の回数、既定30）、`AI_MODEL`（モデル、既定 `claude-haiku-4-5`）も追加できます）

3. **登録しただけでは反映されません**。「Deployments」を開き、いちばん上のデプロイの「…」→「Redeploy」を押して、再デプロイする

#### D. 動作を確認する

1. ブラウザで `公開URL/api/insights`（例：`https://invoice-report-xxxx.vercel.app/api/insights`）を開く。次のように表示されればOK

```
{"available":true,"remaining":3,"limit":3}
```

2. アプリの「月次レポート」画面に「**AIで文章を生成**」ボタンが表示される。押すと、バッジが「**AI生成**」に変わる

| `/api/insights` の表示 | 原因と対処 |
|---|---|
| `"reason":"not_configured"` | `ANTHROPIC_API_KEY` が未登録、または再デプロイしていない |
| `"reason":"limiter_not_configured"` | `UPSTASH_REDIS_REST_URL` / `TOKEN` が未登録、または再デプロイしていない |
| `"reason":"limiter_error"` | Upstash の URL かトークンが間違っている（コピーし直す） |
| `"reason":"limit"` | 今日の利用上限に達した（日本時間で翌日に戻る）。自動集計は使える |
| `"reason":"disabled"` | `AI_ENABLED=false` になっている |

#### 止めたいとき

- すぐにAIだけ止める：Vercel の環境変数に `AI_ENABLED` = `false` を追加して再デプロイ（自動集計は使い続けられます）
- 完全に止める：Claude Console の API keys でキーを削除する（その瞬間から一切使えなくなります）

## 仕様の詳細

### 入金判定のルール

- 残高 ＝ 請求額 − 入金額
- 入金済み：残高が0以下／一部入金：入金額が0を超え請求額未満／未入金：入金額が0
- **支払遅延**：残高があり、支払期日が基準日より前（期日当日は遅延ではありません）。一部入金・未入金より優先して表示
- 遅延日数：基準日 − 支払期日。基準日はサンプルデータでは 2026-09-30 に固定
- 表示ラベル：一部入金のうえ遅延している請求書は「一部入金・遅延」（`statusLabel`）

### 集計の定義

- 売掛金残高：請求書ごとの残高（過入金は含めない）の合計
- 今月の回収予定：期日が基準日の月で、未回収の残高（すでに遅延中のものも含む）
- 回収率：期日が到来した請求書の入金額 ÷ 請求額
- 回収を急ぐべき取引先：現在遅延中の残高が大きい順
- 支払いが遅れがちな取引先：遅延回数（遅れて入金済み＋現在遅延中）が多い順。同数なら平均遅延日数が長い順
- 年齢別残高：期日内 / 1〜30日 / 31〜60日 / 61日超
- 月末売掛金残高：その日時点で請求済み・未入金の合計（月次推移用）

### 画面

- PC：左サイドバー／スマホ：下部タブバー。概要・請求書一覧・取引先別の3画面
- 概要：KPI4つ、年齢別残高、月別の請求・入金・売掛金残高、回収を急ぐべき取引先、支払いが遅れがちな取引先、今月の回収予定
- 請求書一覧：状態・取引先で絞り込み、並び替え。遅延行は色付き。一部入金のうえ遅延は「一部入金・遅延」と表示
- 取引先別：売掛金残高（期日超過を赤で区別）と遅延回数・遅延率・平均遅延日数（PCは表、スマホはカード表示）
- 画面上部の「基準日」を変えると、遅延日数などが再計算される

### CSV取り込みと検証

- 「データ取込」画面で、CSVをドロップまたは選択して取り込む。誤りがなければそのまま取り込み、概要画面へ移動
- 文字コードは UTF-8 を優先し、読めなければ Shift_JIS（Excelの「CSV」保存）として読む
- 見出しは英語（`client` など）でも日本語（`取引先` など）でも可。全角数字・`2026/9/5`・`1,100,000`・`¥5,000` も受け付ける
- 誤りは「**何行目・どの列・どんな誤りか・入力値**」で一覧表示する（空行があっても行番号はずれない）
  - 列の不足／空ファイル／見出しだけ（取り込み不可）
  - 取引先・請求番号が空、請求番号の重複
  - 日付が実在しない・形式違い、支払期日が請求日より前、入金日が請求日より前
  - 請求額が数値でない・0以下、入金額が数値でない・マイナス、入金額が請求額を超える
  - 入金額があるのに入金日がない／入金日があるのに入金額がない
- 誤りのある行があるときは、その行を除いて取り込むかを選べる
- 任意の列として、取引先の**フリガナ**（`client_kana`）も読み込める（請求書発行の宛先検索に使う。列がなくても取り込める）
- 「誤りを含むCSVで、エラー表示を試す」で、検証の動きを確認できる（`public/sample-error.csv`）

### 月次レポート

「月次レポート」画面で、集計結果を文章にします。画面には **どちらで作られた文章か** を必ず表示します。

| 表示 | 中身 |
|---|---|
| **自動集計** | 集計結果から、あらかじめ決めたルールで作る文章（AIは使わない）。**APIキーがなくても常に動く** |
| **AI生成** | Claude API が、集計結果（JSON）をもとに書いた文章。ボタンを押したときだけ生成する |

- 初期表示は必ず「自動集計」。AIは「AIで文章を生成」ボタンを押したときだけ呼ぶ（自動では呼ばない）
- 公開版でキーが未設定・上限到達・API障害のときは、ボタンを出さない／通知を出したうえで「自動集計」の文章を表示する
- AIに送るのは集計結果（取引先名・金額・件数など。約1.3KB）だけで、個別の請求書明細や入金額の一覧は送らない

#### APIキーと料金の安全対策（公開版）

APIキーは **Vercel の環境変数だけ** に置きます（`.env.example` にはキー名のみ）。ブラウザのコードにもGitHubにも入りません。
第三者に使われて料金が膨らまないよう、サーバー側（`api/`）で次の対策をしています。

1. **キーと回数カウンタの両方がそろったときだけAIを有効にする**（カウンタ＝Upstash Redis。どちらかが欠けるとAIは無効で、自動集計のみ）
2. **1日の利用回数に上限**：訪問者ごと（IPを暗号化して数える）に3回／サービス全体で30回（日本時間で日替わり。`AI_DAILY_LIMIT_PER_IP`・`AI_DAILY_LIMIT_TOTAL` で変更可）。1人が全体の枠を使い切れないよう、訪問者の上限を先に判定
3. **受け付ける入力を絞る**：形・文字数・件数・値の範囲を検証した集計値だけ（自由な文章は通さない）。取引先名も1行30文字に整形
4. **出力の長さを固定**（`max_tokens`）・**1回の呼び出しのみ**（失敗しても自動リトライしない）・30秒で打ち切り
5. **別サイトからの呼び出しを拒否**（Originの検査）、カウンタが壊れているときも使わせない
6. **緊急停止スイッチ**：環境変数 `AI_ENABLED=false` で即座にAIを止められる
7. （念のため）Anthropic Console 側で、APIキーに **月の利用額の上限** を設定しておく

使うモデルは、既定で軽量・低コストの **Claude Haiku 4.5**（`claude-haiku-4-5`）です。環境変数 `AI_MODEL` で変更できます。

1回あたりの目安は、入力が約1.5千トークン、出力が最大1.5千トークンで、約1円（最大でも2円弱）です。
サービス全体で1日30回までなので、最悪でも **1日あたり約50円、1か月で約1,500円** に収まる設計です（実際の利用は通常これよりずっと少なくなります）。

### 請求書PDFの発行

「請求書発行」画面で、取引先ごとの請求書をPDFで出力できます（データを読み込んでいなくても使えます）。

- **宛先の検索**：入力に応じて候補が絞り込まれる。名前の一部（例：「物流」→ アルファ物流）でも、フリガナ（例：「と」→ 東和建設、「さ」→ サクラ食品、「ぶつりゅう」→ アルファ物流）でも探せる。
  ひらがな／カタカナ、全角／半角、大文字／小文字の違いは区別しない。キーボードの↑↓で選び、Enterで決定、Escで閉じる
- **フリガナ**：請求データ（CSV）の任意の列 `client_kana`（または `フリガナ`）から読み込む。新しい取引先で発行するときは、その場で入力できる
- **宛先の履歴**：一度発行した宛先（と請求番号）は、このブラウザに残り、データを読み込んでいなくても次回の候補に出る。請求番号もその続きから採番される
- **データ未読み込みのとき**：その旨と、「サンプルデータを読み込む」ボタンを画面内に表示する（読み込んでも発行画面のまま）
- **請求番号の自動採番**：`INV-年月-連番`（例：`INV-202609-011`）。発行日と同じ年月の既存の最大連番＋1。続けて発行しても重複しない
- **明細**：品目・数量・単価・税率（10%／軽減8%／非課税）。行の追加・削除ができる
- **金額の計算**：小計・消費税・合計を自動計算。消費税は **税率ごとの合計に対して1回だけ円未満切り捨て**（適格請求書の考え方。明細ごとには丸めない）
- **記載事項**：発行日、支払期日（既定は発行日の翌月末）、税率ごとの対象額と消費税額、登録番号（任意）、お振込先、備考
- **入力チェック**：宛先・発行元・明細の不足、支払期日が発行日より前、登録番号の形式（T＋13桁）、数量・単価の値、合計0円 などを、発行前に一覧で知らせる
- 「発行と同時に請求データへ追加」をオンにすると、発行した請求書が売掛金・回収予定に反映される
- 発行元（会社名・住所・振込先など）は、このブラウザにだけ保存される（サーバーには送らない）。初期値の会社名・住所・登録番号（`T1234567890123`）はすべてダミー
- PDFの生成は `@react-pdf/renderer`。日本語フォントは **Noto Sans JP**（SIL Open Font License。`public/fonts/` に同梱、日常で使う漢字・かな・記号に絞って軽量化）。
  重いライブラリとフォントは、**「請求書PDFを作成」を押したときに初めて読み込む**ので、通常の画面表示は重くならない
